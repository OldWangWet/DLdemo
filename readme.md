# 机器学习和深度学习练习

此项目用于机器学习和深度学习练习，具体算法、公式和实现说明见各算法目录中的 `readme.md`。

## 目录组织与共同约束

每个算法目录按以下结构逐步建设；尚未完成的阶段不表示已经具备对应能力。

```text
算法目录/
├── main.py          # 使用 sklearn 演示算法与数据集
├── readme.md        # 算法原理、公式和手算示例
├── basic/           # 清晰、最小可用的公式实现
├── optimized/       # 算法与数学计算的改进
└── sklearn_impl/    # 按 sklearn 源码实现模型及主要能力
```

- 除非用户明确指定，三个阶段的算法实现和优化均以 sklearn **已经实现的源码方法**为依据；源码中的优化设想、TODO 或其他合理但未实现的方法，不自行加入。
- 在各阶段的 README 中记录参考的 sklearn 版本，以及对应类、方法或源码位置，避免混用不同版本的行为。
- 所有手动实现使用 Python，可以使用 NumPy/SciPy；不考虑编译、语言替换等语言级优化。sklearn 可用于数据加载和对照验证；`sklearn_impl/` 还可以复用 sklearn 的基类、输入校验、标签编码及其他公共框架与辅助工具，但目标算法的训练和预测计算必须手动实现，不调用 sklearn 的目标模型或其内部训练、预测方法代替手动计算。
- 三个阶段都需要说明实际支持范围。代码组织、基本检查和必要调用接口不算算法优化；前一阶段已有的能力不算后一阶段的新增收益。

## 三个阶段的职责

### `basic/`：把公式实现清楚

针对上层 `main.py` 使用的数据集，按上层 README 的公式实现算法，优先保证原理清晰、代码简洁、示例正确。

允许采用源码中必要或普遍使用的基础计算方法，例如对数域计算、平滑和必要的数组运算。提供最小可用接口，通常为 `fit` 和 `predict`，以及使公式在有效定义域内运行的基本检查，例如样本数量、特征维度及取值范围。

本阶段不追求完整 sklearn 接口、全部参数选项或性能。原则上使用示例需要的数据表示和一次性训练，不提前引入稀疏、样本权重、增量训练等扩展。

**完成依据：** 手算示例与公式一致；在相同数据和参数下与 sklearn 对照；README 写清输入假设、参数限制和退化边界。

### `optimized/`：改进算法与数学计算

以实际的 `basic/` 实现为基线，系统采用 sklearn 已实现的算法步骤、数学等价变形和数值方法。重点是计算什么、如何组织计算、如何避免无用计算或数值误差。

典型内容包括批量计数或评分、代数变形、重复统计的消除、稳定的对数归一化，以及均值方差合并等数学方法。矩阵运算可以作为计算式组织的改进，但不能仅凭“减少 Python 循环”就认定复杂度降低或性能提高。

原则上沿用基础版的数据表示和一次性训练范围。可以增加验证数学计算所需的最小得分或概率接口，但接口新增本身不计为优化；不扩展 estimator 协议、完整输入输出规范或资源管理能力。

**边界：** 保留统计量合并公式不等于实现 `partial_fit`；稳定概率归一化不等于完整复现概率输出接口；矩阵评分不等于支持 CSR。增量接口、稀疏路径等属于第三阶段。

需要区分两种变化：等价变形在相同模型参数下应保留分类规则，允许合理浮点误差；源码已有的算法选项或数值保护可能改变分类规则或有效参数，必须单独说明并与同设置的 sklearn 对照，不能宣称结果不变。

**完成依据：** 逐项记录源码依据、相对基础版的实际变化、收益与适用条件；比较必要的统计量、参数、得分和预测。声称性能收益时提供可复现测量，声称数值收益时验证对应数值边界，不能只比较准确率，也不能要求每项优化都必然加速。

### `sklearn_impl/`：按 sklearn 源码实现模型

参考指定版本的 sklearn 源码，手动实现目标算法的训练与预测计算。优先保证计算流程清楚、模型可运行，不要求完整复现 sklearn 的全部接口行为。

本阶段默认要求：

- 记录参考版本，以及对应类、方法或源码位置。
- 实现主要参数及源码已有的模型能力，优先支持 CPU 上的 NumPy/SciPy 路径。
- 可以复用 sklearn 的基类、输入校验、标签编码及其他公共流程。
- 不调用 sklearn 的目标模型或其内部训练、预测方法代替手动计算。
- 不自行加入源码未实现的算法优化或资源策略。
- README 说明实际支持范围、已知差异和未实现内容。

默认验证：

- 运行上层示例，与同数据、同参数的 sklearn 比较预测结果。
- 不要求新增自动化测试、运行 sklearn 原始测试、全面覆盖异常路径或进行性能和内存测量。
- 用户明确要求测试、完整行为兼容或性能优化时，再补充相应实现与验证。

默认不要求实现 Array API/GPU、元数据路由、回调、HTML 展示、跨版本序列化，以及异常和警告的逐字符兼容。

**完成依据：** 模型实现及示例对照可运行，README 如实描述支持范围。不将这一阶段默认称为“完整行为复现”。

## 跨阶段内容如何归属

一个功能可能同时涉及数学计算、模型能力和接口行为，应按具体改动归属，不能因为它出现在 sklearn 的同一个方法里，就全部算作算法数学优化。

| 具体内容 | 归属与说明 |
|---|---|
| 对数计算、基础平滑、必要数组运算 | `basic/` 可先实现；后续沿用不算新增优化 |
| 代数变形、批量计数或评分、稳定归一化 | `optimized/` 的算法数学计算；需说明实际增量 |
| 均值方差合并公式 | `optimized/` 的数学方法 |
| `partial_fit`、批次状态与类别契约 | `sklearn_impl/` 的增量能力和接口行为 |
| 小参数截断等源码数值保护 | 计算部分可归 `optimized/`；完整参数、警告兼容归 `sklearn_impl/`，按需实现 |
| 最小得分或概率方法 | 可用于第二阶段验证；方法名、输出规范等不是数学优化 |
| CSR 支持、稀疏乘法与存储 | `sklearn_impl/` 的数据能力与资源优化 |
| 样本权重、自定义先验、参数选项 | `sklearn_impl/` 的模型能力；其数学原理可在前两阶段说明 |
| 复制控制、内存分块、线程和并行策略 | `sklearn_impl/` 的资源优化，限源码已有方法 |
| 测试中的线程限制、预热和计时设置 | 验证条件，不属于模型实现的优化 |

后续阶段继承前一阶段的计算方法，按新增内容验收。若某个算法没有适合第二阶段的新增方法，可以说明原因并保留已有计算，不为凑优化项扩展第三阶段能力。
